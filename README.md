# 부서 건강도 설문 분석 대시보드

사내 부서 건강도 설문 데이터를 조직 계층에 따라 집계/조회하는 대시보드입니다.
현재 단계는 **구조/파이프라인 목업**이며, 실제 설문 데이터는 추후 사내에서
`xlwings` 로더로 채워 넣습니다.

## 구성

```
config/schema.json          엑셀 컬럼 <-> JSON 필드 매핑 (단일 소스)
scripts/schema_utils.py     스키마 로딩 + 롤업(가중평균) 계산 로직
scripts/generate_dummy_data.py   더미 데이터 생성 (5레벨 조직 예시)
scripts/xlwings_loader.py   DRM 엑셀 4번째 시트 -> JSON 변환 (실 데이터용)
scripts/segment_loader.py   DRM 엑셀의 부서별 "문항별 결과" 시트 -> 세그먼트 JSON 변환 (실 데이터용)
scripts/xlwings_utils.py    위 두 로더가 공유하는 Excel 연결 헬퍼 (DRM 복호화 우회용 open_or_attach())
scripts/generate_dummy_segment_data.py  더미 세그먼트 데이터 생성
data/dummy_survey_data.json 생성된 더미 부서별 설문 데이터
data/org_map_2026Q2.json    샘플 "이전 회차" 조직 계층 JSON
data/segment_data.json      생성된 더미 세그먼트(인구통계) 데이터
dashboard/index.html        단일 HTML 대시보드 (조회모드 + 관리자모드)
```

## 데이터 파이프라인

1. **엑셀 -> JSON**: `python scripts/xlwings_loader.py "경로/설문.xlsx"`
   - DRM 파일은 openpyxl 등으로 열 수 없으므로 xlwings로 실제 Excel
     애플리케이션을 구동해 4번째 시트(`wb.sheets[3]`)를 읽습니다.
   - `config/schema.json`의 컬럼 매핑(A~BD)에 따라 부서레벨/인원/영역·항목·문항
     점수를 파싱하여 `data/survey_data.json`으로 저장합니다.
   - 전년비(L~N)가 `-`인 경우 문자열 `"-"` 그대로 유지되며, 대시보드에서
     "데이터 없음"으로 표시됩니다.
   - **"읽기 전용이거나 손상되었거나 암호화되어 있습니다" 오류가 뜨는 경우**:
     더블클릭으로는 정상적으로 열리는 파일이 스크립트로는 이 오류를 내는 대표
     원인은 Excel의 확인 대화상자(예: "읽기 전용으로 여시겠습니까?", 또는 DRM/
     보안 플러그인 자체의 팝업)입니다 — 사람이 더블클릭으로 열면 그냥 무심코
     넘기는 창인데, 스크립트로 자동화하면 그 대화상자에 아무도 응답하지 못해
     열기 자체가 멈추거나 실패하고, 그 결과가 이 오류로 나타납니다.
     `scripts/xlwings_utils.py`의 `open_or_attach()`는 3단계로 대응합니다:
     (1) `ignore_read_only_recommended=True` 등 Excel COM API 옵션으로 Excel
     자체의 읽기전용 확인창을 억제, (2) 그래도 `pywintypes.com_error`로
     `-2146777998`(0x800AC472, "대화상자가 열려 있어 접근할 수 없음") 오류가
     나면 — 이건 Excel 네이티브 옵션으로는 못 막는 제3의(보통 DRM 플러그인 자체)
     대화상자가 떠 있다는 뜻이므로 — 그 창을 찾아 Enter(기본 버튼)로 자동 응답
     시도, (3) 그래도 안 되면 몇 차례 재시도. 이 정도면 **44개 파일 전부 자동으로
     처리되는 게 기본 동작**이어야 합니다. 콘솔에 "Excel 대화상자 감지: '...'"가
     뜨면 어떤 창을 자동으로 닫았는지 그대로 보여주니 의도와 다르게 동작하면
     바로 알 수 있습니다. 그래도 특정 파일에서 계속 실패하면, 그 파일만 먼저
     평소처럼 더블클릭으로 열어서 켜둔 채로 스크립트를 다시 실행하세요 — 새로
     열지 않고 이미 열려 있는 그 창에 자동으로 연결합니다. 이 경우 스크립트가
     끝나도 그 창은 그대로 남겨두고 닫지 않습니다.

2. **조직 계층 JSON**: 대시보드 관리자 모드에서 부서 노드를 드래그앤드롭이나
   ▲▼ 버튼으로 재배치한 뒤 "현재 회차로 저장" 버튼을 누르면
   `org_map_<회차명>.json`
   (`{ "round": ..., "map": { "부서코드": "상위부서코드|null" }, "order": ["부서코드", ...] }`)
   파일이 다운로드됩니다. 다음 회차 작업 시 "이전 회차 불러오기"로 이 파일을
   불러와 변경된 부분만 수정하면 됩니다.
   - 대시보드를 열면 처음엔 항상 내장된 예시(더미) 데이터가 떠 있는 상태입니다.
     "부서 데이터 불러오기"로 실제 설문 데이터를 불러오지 않은 채 관리자 모드로
     바로 가서 "현재 회차로 저장"을 누르면, 지금 화면에 떠 있는 게 실제 더미
     데이터이므로 저장되는 파일에도 더미 코드(`C000`, `H100` 등)가 그대로
     담깁니다 — 버그가 아니라 "지금 이 화면이 곧 저장될 내용"이라는 원칙대로
     동작한 것이지만, 놓치기 쉬운 함정이라 이걸 막는 안전장치를 두 개 넣었습니다:
     아직 실제 데이터를 불러오지 않았으면 관리자 모드 상단에 빨간 경고 배너가
     항상 보이고, 그 상태에서 "현재 회차로 저장"을 누르면 그대로 진행할지
     확인하는 창이 한 번 더 뜹니다.
   - `order`는 같은 부모를 가진 부서들 사이의 형제 순서(위/아래 배치 순서)를
     저장합니다. `map`의 키 순서로는 이를 안정적으로 보존할 수 없는데,
     자바스크립트 엔진이 `"1001"`, `"9000"`처럼 숫자로만 이루어진 문자열 키를
     `Object.keys`/`Object.entries` 호출 시마다 값과 무관하게 오름차순으로
     자동 재정렬하기 때문입니다 — 실제 부서코드가 순수 숫자인 경우 매우 흔한
     상황이라, 이 재정렬을 그대로 뒀다면 관리자가 순서를 바꿔도 저장·재로드
     시 다시 오름차순으로 되돌아가는 버그가 있었습니다. 그래서 형제 순서는
     `map`과 별개로 `order` 배열에 명시적으로 저장합니다. `order`가 없는
     구버전 파일은 `map`의 키 순서로 대체됩니다.
   - 엑셀 A컬럼의 부서레벨(1~5)은 참고용 숫자일 뿐이며, 실제 상하위 관계와
     롤업 계산의 기준은 이 JSON 트리입니다.
   - 부서 데이터를 새로 불러올 때 그 부서의 이전 상하위 관계를 알 수 없는 경우
     (실 데이터 최초 로드, 조직도 파일과 코드가 안 맞는 경우 등), 무작정 전부
     최상위로 흩어놓지 않습니다. **부서레벨이 1인 부서가 정확히 하나면 그 부서를
     기본 최상위로 삼고, 부서레벨이 2인 부서들만 자동으로 그 아래에 배치**합니다
     (레벨2는 레벨1 산하라는 게 거의 확실하기 때문). 레벨3 이하는 여러 레벨2 부서
     중 정확히 어디 속하는지 자동으로 판단할 수 없으므로 최상위 상태로 남겨두고
     관리자가 직접 드래그로 배치하도록 합니다 (레벨1 부서가 없거나 여러 개면
     예전처럼 전부 최상위로 표시).
   - **"이전 회차 불러오기"는 순서와 무관하게 동작하지만, 조직도 파일의 부서
     코드가 현재 화면에 떠 있는 설문 데이터와 하나도 겹치지 않으면** (예: 대시보드를
     새로 열어 아직 내장 더미 데이터만 있는 상태에서 저장해둔 조직도 파일부터
     불러온 경우) 위 자동 재배치 로직이 통째로 새로 만들어버려 방금 불러온
     파일의 구조가 화면에 전혀 반영되지 않을 수 있습니다. 이 경우 파일의
     map/order를 가공 없이 그대로 적용하고 안내 문구를 보여주므로, 상단 "부서
     데이터 불러오기"로 그 조직도에 맞는 설문 데이터를 불러온 뒤 조직도 파일을
     한 번 더 불러오면 정상적으로 맞춰집니다.

3. **본사 벤치마크 JSON**: 관리자 모드 하단 "본사 벤치마크 입력"에서 영역별 점수
   3개(즐거운일/함께하는동료/자랑스러운회사)를 직접 타이핑하고 "본사 값 저장"을
   누르면 `hq_benchmark_<회차명>.json`
   (`{ "round": ..., "hq_benchmark": { "즐거운일": 숫자|null, ... } }`)
   파일이 다운로드됩니다. 엑셀 파이프라인과 완전히 무관한 별도 값이며, "불러오기"로
   이 파일을 다시 불러오면 값이 복원됩니다. 아직 입력하지 않았거나 값이 없으면
   부서 현황 탭에는 에러 없이 "본사 데이터 미입력" 안내만 표시됩니다.

4. **롤업(집계)**: 하위 부서 -> 상위 부서로 점수를 올릴 때는 응답인원 가중평균을
   사용합니다 (`scripts/schema_utils.py`의 `rollup()`과 `dashboard/index.html`의
   동일 로직 `rollup()`이 서로 미러링되어 있습니다). 조직 트리 상 자식이 없는
   노드(예: 하위 조직이 없는 레벨2 부서)는 자기 자신의 원본 응답 데이터를
   그대로 사용합니다.

5. **미분류 인원 분석**: 위 롤업은 자식이 있는 조직의 점수를 **항상 자식들의
   가중평균으로만** 계산하고, 그 조직 자신의 원본 응답 데이터(엑셀 그 조직 자체
   행의 응답인원/점수)는 쓰지 않습니다. 그런데 하위 조직 응답인원 합이 상위 조직
   자체 응답인원보다 적은 경우가 있습니다(예: A플랫폼 자체 응답 50명, 하위 3개
   조직 합 40명 -> 10명이 그 어떤 하위 조직에도 속하지 않음). 이 10명의 점수는
   원본 데이터 어디에도 없으므로, 가중평균 공식을 역으로 풀어서 추정합니다 —
   `S_미분류 = (S_total × N_total − Σ(s_i × n_i)) / N_미분류` (영역별·항목별
   각각 독립 계산, `computeUnclassified()`). 하위 조직 중 하나라도 특정 영역/
   항목 점수가 없으면 그 항목은 추정하지 않고 "-"로 남깁니다(잘못된 값을
   추정하느니 표시하지 않는 쪽을 택함). `N_미분류 <= 0`(하위 합이 상위와 같거나
   큼)이면 분석 대상에서 제외됩니다. 표시 위치는 위 "부서 현황" 탭 설명과 경영진
   요약의 "미분류 인원 영향이 큰 조직" 참고 — 두 곳 모두 표본(미분류 인원 수)이
   적을수록 추정 오차가 커질 수 있다는 주의 문구를 항상 함께 보여줍니다.

6. **세그먼트 데이터**: `python scripts/segment_loader.py "경로/설문.xlsx"` — 마스터
   설문 데이터와는 완전히 다른 소스로, 부서마다 별도로 존재하는 "문항별 결과: (조직명)"
   상세 시트(근속/성별/연령/직군/경력개발단계/학력/사업부 비교별 점수)를 읽어
   `data/segment_data.json`으로 저장합니다. 4번째 마스터 시트와 달리 **부서마다
   세그먼트 컬럼 구성(예: 비교 대상 사업부 수)이 다를 수 있어서 컬럼을 고정 letter로
   하드코딩하지 않고, 매 시트마다 3~4행 헤더(대분류/소분류)를 런타임에 읽어 컬럼
   위치를 동적으로 매핑**합니다 (`segment_loader.py`의 `build_column_map()`).

   조직별 상세 데이터가 **한 워크북 안의 여러 시트**로 되어 있든 **조직마다 별도
   파일**(예: 전사 포함 총 44개)로 되어 있든 둘 다 지원합니다. **폴더 경로를 그대로
   넘기면** 그 안의 `.xlsx` 파일을 전부 찾아서(하위 폴더까지 보려면 `--recursive`)
   각 파일의 모든 시트를 독립적으로 스캔합니다 — Windows cmd/PowerShell에서는
   `*.xlsx` 같은 글롭이 자동으로 펼쳐지지 않아서, 폴더 지정은 셸의 글롭 전개가
   아니라 스크립트 자체에서 처리합니다:
   ```
   python scripts/segment_loader.py "C:\segments" --expected-count 44
   ```
   `--expected-count`를 주면 실행 끝에 "44/44개 파싱됨" 또는 몇 개가 비었고
   survey 데이터 기준 어떤 부서명이 매칭 안 됐는지까지 바로 알려줍니다.

   **누적 저장된 부서 수가 실제 파일 수보다 많게 나오면** (실제 사례: 파일은
   44개인데 68개 부서로 누적) `data/segment_data.json`에 예전에 들어간 부서가
   그대로 남아있어서입니다 — 이 스크립트를 여러 번 나눠 돌리는 것(43개 파일을
   한 번에 다 못 열 때)은 의도된 동작이라 기존 파일에 계속 누적하지만, 실제
   부서 데이터를 아직 안 불러왔을 때 만든 더미 샘플(`data/segment_data.json`에
   커밋되어 있는 24개 더미 부서)처럼 **지금은 더 이상 유효하지 않은 옛날 항목**도
   똑같이 계속 누적되는 문제가 있었습니다. 지금은 실행 시점에 이미 읽어들인
   `survey_data.json`(또는 `dummy_survey_data.json`) 기준 유효한 dept_code
   목록에 없는 부서는 기존 파일에서 자동으로 제거하고 새로 파싱한 부서만 병합
   합니다 (제거된 부서명/코드는 콘솔에 그대로 출력됩니다). 즉 실제 44개 조직의
   survey 데이터를 먼저 불러온 뒤 이 스크립트를 돌리면, 몇 번을 나눠 돌리든
   최종적으로는 정확히 44개만 남습니다.

   **불러온 세그먼트 데이터가 부실해 보이면** (일부 세그먼트만 나오거나 점수가
   대부분 비어있는 경우) `--verbose`를 붙여서 다시 돌려보세요 — 시트마다 대분류/
   소분류가 몇 개씩 잡혔는지, 영역/항목 레이블이 몇 개 발견됐는지를 그대로
   출력해서, row 3/4 헤더 파싱이 컬럼을 놓쳤는지 아니면 영역/항목 행(row 9~)
   스캔이 행을 놓쳤는지 바로 구분할 수 있습니다. 영역이 3개(즐거운일/함께하는
   동료/자랑스러운회사) 미만으로 잡히면 경고도 함께 뜹니다.
   - 실제로 있었던 사례: 44개 조직별 파일 하나하나가 **여러 시트**로 되어 있고,
     "문항별 결과: (조직명)" 제목은 한 시트(예: Sheet1, 표지성 시트)에만 있고
     실제 A~EP열/1~38행 데이터 그리드는 제목이 없는 **다른 시트**(예: Sheet2)에
     있는 경우, 제목이 있는 시트만 읽으면 그 시트에 우연히 있던 일부(예:
     즐거운일 영역만)만 들어가고 나머지 영역은 통째로 빠지는 문제가 있었습니다.
     지금은 (1) 부서명은 워크북 안의 아무 시트에서나 제목을 찾아서 확보하고,
     (2) 실제 데이터 그리드는 제목 유무와 무관하게 **워크북의 모든 시트를 구조적으로
     파싱해보고 영역(즐거운일/함께하는동료/자랑스러운회사)이 가장 많이 발견되는
     시트**를 그 부서의 데이터로 채택합니다. 컬럼 범위(A~EP, 세그먼트는 F열부터)와
     행 범위(1~38, 영역/항목 스캔은 9행부터)는 기존 기본값과 그대로 일치합니다.
   - 두 번째로 있었던 사례: 워크북에 시트가 3개 이상 있고, 실제 데이터가 있는
     시트가 "1.문항별 결과"처럼 **시트 이름 자체에 "문항별 결과"라는 이름이
     붙어 있는데도**, 영역 개수만으로 비교하다 보니 그와 무관한 다른 시트(예:
     Sheet3)가 우연히 더 많은/비슷한 개수의 "영역처럼 보이는 행"을 갖고 있어서
     엉뚱하게 그 시트가 선택되는 문제가 있었습니다. 지금은 **워크북 안에 이름에
     "문항별 결과"가 들어간 시트가 하나라도 있으면 그 시트(들)만 후보로 좁혀서**
     그 안에서 최선의 시트를 고르고, 그런 이름의 시트가 전혀 없을 때만(이전
     사례처럼 제목이 다른 시트의 셀 내용에만 있는 경우) 워크북의 모든 시트를
     대상으로 영역 개수 비교를 합니다.
   - 세 번째로 있었던 사례: 올바른 시트를 찾아도 그 안에서 데이터가 **군데군데
     빠지는(파편적으로 들어가는)** 문제. 원인은 컬럼 폭 가정이었습니다 — 기존 코드는
     모든 소분류가 "점수+전년대비" 2컬럼 쌍이라고 가정하고 항상 2칸씩 건너뛰며
     읽었는데, "사업부 비교"처럼 **비교 대상 부서 하나하나가 전년대비 없이 점수
     1컬럼짜리**인 경우 이 가정이 깨져서, 특정 부서의 점수 컬럼이 바로 앞 부서의
     "전년대비" 컬럼으로 잘못 읽히고 그 뒤로도 계속 한 칸씩 밀려 읽히는 문제가
     있었습니다(이전에 보고된 "R120/T121만 보인다" 현상과 동일한 원인). 지금은
     고정폭 대신 **Row3/Row4 헤더가 실제로 몇 칸 연속 동일한지를 그때그때 측정**해서
     컬럼 폭을 잡습니다 — 2칸 연속이면 점수+전년대비 쌍으로, 1칸이면 전년대비 없는
     점수 전용 컬럼으로 처리하고, 매 소분류 경계마다 다시 동기화되므로 한 소분류의
     폭이 특이해도 그 뒤 컬럼들이 밀리지 않습니다.

   이 스크립트는 실제 워크북 샘플 없이 텍스트 설명만으로 작성되었으므로, 파일 상단
   docstring에 적어둔 가정(병합 헤더 처리 방식, 점수/전년대비 컬럼 쌍 해석 등)이
   실제 시트와 다르면 알려주시면 바로 고치겠습니다 — `python scripts/generate_dummy_segment_data.py`로
   만든 `data/segment_data.json`을 대시보드에 불러와 화면 동작 자체는 먼저 확인해볼 수 있습니다.

## 대시보드 실행

`dashboard/index.html` 을 브라우저로 열면 바로 동작합니다 (별도 서버/빌드 불필요).
처음에는 내장된 더미 데이터로 렌더링되며, 상단의 "부서 데이터 불러오기" /
관리자 모드의 "이전 회차 불러오기" 버튼으로 실제 JSON 파일을 불러올 수 있습니다.

- **조회 모드**: 좌측 조직도에서 부서 선택 -> 브레드크럼/드릴다운으로 이동.
  선택한 부서 기준으로 아래 7개 탭이 갱신됩니다.
  1. **부서 현황**: 경영진 요약 역할의 메인 탭. 상단에 본사 벤치마크 비교 카드(레벨1
     롤업 점수 vs 관리자 모드에서 수기 입력한 본사 점수, 영역별 차이), 그 아래 영역별
     점수(전년비 포함), 항목별 점수(12개)를 보여줍니다. 문항 단위(30개, 엑셀 AA~BD
     컬럼) 상세는 화면에 노출하지 않습니다 — 데이터 준비 부담을 줄이기 위해 조회
     모드는 요약 수준까지만 보여주는 게 목적입니다. 응답률/부서장 정보는 탭과
     무관하게 상단 부서 헤더에 항상 표시됩니다. 이 조직 자체의 응답인원과 하위
     조직 응답인원 합이 다르면(**미분류 인원**, 아래 설명) 벤치마크 카드 바로 아래에
     경고 카드가 함께 표시되고, 좌측 조직도에도 "미분류 인원 있음" 배지가 붙습니다.
  2. **핵심동인분석**: 12개 항목의 표준화 회귀계수(베타)로 "회사만족"에 대한 영향력을 순위화.
     전사 응답 데이터로 한 번만 계산하며, 특정 부서를 선택하면 전사 베타 × (전사평균-부서점수)
     로 "전사 기준 영향력 대비 이 부서가 취약한 항목"을 함께 보여줍니다 (표본이 적은 부서에
     별도 회귀분석을 돌리지 않는 이유는 스펙 참고).
  3. **랭킹·이상치**: 선택 부서의 형제 부서(동일 상위조직 하위)들끼리만 순위/Z-score/IQR
     이상치를 비교하고, 선택한 조직 산하 전체에서 위험군(영역 점수 하위 10% 또는 전년비
     하락폭이 그룹 평균 초과) 부서 리스트를 보여줍니다.
  4. **응답신뢰도**: 응답률 구간별 신뢰/주의/경고 배지, 전사 부서 응답률-점수 산점도(상관계수 포함).
  5. **리더십비교**: 이번 회차 부서장ID 기준으로 담당 부서들을 묶어 가중평균 점수/규모를 비교.
  6. **조직편차**: 선택 부서에 하위 조직이 있을 때만 활성화되며, 하위 부서 점수의 평균/표준편차/
     범위와 "고르게 우수·저조" vs "편차가 큰 조직" 라벨, min-max 분포 트랙을 보여줍니다.
  7. **세그먼트비교**: 근속/성별/연령/직군/경력개발단계/학력 등 인구통계 세그먼트별로 영역·항목
     점수를 비교합니다 (문항 단위 세부는 제공하지 않음). 마스터 설문 데이터와는 완전히 별도의
     JSON 파일(상단 "세그먼트 데이터 불러오기")로 불러오며, 부서별로 로드해뒀는지 여부에 따라
     탭 내용이 달라집니다 — 자세한 파일 형식은 아래 "세그먼트 데이터 파이프라인" 참고.

  분석 임계치(응답률 신뢰도 구간, 이상치 Z-score, 위험군 하위 백분위, 표본 부족 기준 등)는
  모두 `dashboard/index.html`의 `ANALYSIS` 상수에 모여 있어 조정이 쉽습니다.

  핵심동인분석의 막대그래프, 응답신뢰도·리더십비교의 산점도, 조직편차의 분포 그래프에는
  모두 **"그래프 이미지로 복사"** 버튼이 붙어 있습니다. 클릭하면 해당 그래프를 PNG
  이미지로 클립보드에 복사해 보고서/메신저/워드에 Ctrl+V로 붙여넣을 수 있습니다
  (클립보드 이미지 복사가 막힌 브라우저에서는 자동으로 PNG 파일 다운로드로 대체됩니다).
  모든 그래프는 외부 라이브러리 없이 inline SVG로 그려서 캔버스에 그대로 그려 넣는
  방식이라(`svgToPngBlob`), 캡처 기능도 완전히 오프라인으로 동작합니다.
- **경영진 요약 모드**: 조회 모드의 드릴다운과 무관하게 **항상 전사(최상위) 관점 고정**으로,
  하위 조직 전체를 훑어 주요 이슈만 뽑아 한 화면에 모아 보여주는 읽기 전용 보고서
  화면입니다. 드릴다운/편집 기능은 없습니다. 화면 전체가 **표(table) 위주로만
  구성**되어 있는데, Confluence 등 리치텍스트 에디터에 붙여넣었을 때 표 구조와
  굵게/배경색 정도의 인라인 스타일은 대체로 유지되지만 flex/grid 같은 레이아웃
  CSS는 붙여넣기 과정에서 사라지는 경우가 많기 때문입니다 — 그래서 이 화면만은
  다른 탭들과 달리 카드/그리드 배치를 쓰지 않습니다.
  - **핵심 지표 요약**: 전사 종합점수, 영역별 점수 3개, 전사 응답률, 전년비(평균)를
    한 줄짜리 표로 표시.
  - **Lv2 조직별 현황**: `dept_level === 2`인 모든 조직을 하나도 빠짐없이 개별 행으로
    나열하고, 종합점수 75점(`EXEC_SUMMARY.GOOD_SCORE_THRESHOLD`) · 전년비(영역 3개
    평균) 상승/하락을 기준으로 **우수(점수↑·전년비↑) / 양호(점수↑·전년비↓) /
    개선(점수↓·전년비↑) / 주의(점수↓·전년비↓)** 4분류를 적용합니다. "근거" 컬럼에
    실제 점수·전년비 수치와 어느 기준을 충족했는지를 그대로 문장으로 풀어 써서
    등급표가 블랙박스가 되지 않게 했습니다. 이 부서 자체의 전년비 보고값이 없으면
    (rollup()이 area_yoy를 자식 가중평균이 아니라 항상 그 부서 자기 자신의 원본
    값에서만 가져오기 때문에 흔히 생깁니다) 추측하지 않고 "분류불가"로 표시합니다.
    응답인원이 6명(`EXEC_SUMMARY.LOW_SAMPLE_THRESHOLD`) 미만인 조직은 4분류와
    별개로 "비고" 컬럼에 "표본 부족(N명)"으로 항상 따로 표기합니다.
  - **위험군 부서 통합 리스트**(기본 상위 10개): 이상치(|Z|≥2), 응답률 50% 미만,
    전년비 하락(그룹평균 초과 하락폭) 3개 조건을 트리 전체에서 통합 스캔해
    사유 태그(복수 가능)와 함께 심각도 순으로 정렬합니다. 특정 부서의 형제
    그룹 안에서만 보는 랭킹·이상치 탭과 달리, 조직 전체를 한 번에 스캔합니다.
    "근거" 컬럼에 실제 Z-score/그룹평균/응답률 수치를 함께 표시합니다.
  - **미분류 인원 영향이 큰 조직 Top N**(기본 5개): 아래 "미분류 인원 분석" 문단 참고.
    미분류 비중과 추정 점수-하위평균 차이를 더한 값으로 정렬해, 둘 중 하나라도 크면
    상위에 노출되게 했습니다 (비중은 크지만 차이는 작은 조직, 반대로 비중은 작지만
    차이가 큰 조직 모두 놓치지 않도록).
  - **조직 내부 편차 큰 조직 Top N**(기본 5개): 하위 부서가 2개 이상인 모든 조직을
    대상으로 하위 부서 종합점수의 표준편차 기준 정렬, 최고/최저 부서명을 함께 표시.
  - **핵심동인 Top N**(기본 3개): 전사 기준 표준화 회귀계수(베타) 절대값 상위 항목과
    자동 생성 코멘트("OO 항목이 가장 큰 영향 요인으로 나타남").
  - **부서장 리더십 이상치**(기본 상위 5명): 전체 부서장 평균 대비 점수 편차가 큰
    순서(고성과/저성과 모두 포함)로 정렬, 그룹평균·편차·Z-score를 함께 표시.
  - 화면 하단에 데이터 갱신 시점(부서 데이터를 마지막으로 불러온 시각)을 작게 표시합니다.
  - 각 섹션의 Top N 개수·분류 임계값은 `dashboard/index.html`의 `EXEC_SUMMARY` 상수
    (`RISK_TOP_N`/`VARIANCE_TOP_N`/`DRIVER_TOP_N`/`LEADER_TOP_N`/
    `GOOD_SCORE_THRESHOLD`/`LOW_SAMPLE_THRESHOLD`/`UNCLASSIFIED_TOP_N`)에서 조정합니다.
  - 상단 **"Confluence에 복사"** 버튼을 누르면 이 화면 전체를 `text/html` 클립보드
    항목으로 복사합니다 (표 전체 복사 기능과 동일한 방식 — Ctrl+C/V가 아니라
    Clipboard API로 HTML을 직접 써 넣어, 리치텍스트 에디터가 진짜 `<table>`으로
    인식하게 합니다). Confluence 편집창에 Ctrl+V 하면 표/굵게/배경색이 그대로
    붙여넣어집니다. 클립보드 API가 막힌 브라우저에서는 자동으로 전체 선택 +
    복사 방식으로 대체됩니다.
- **관리자 모드**: 각 부서 오른쪽의 **▲▼ 버튼**으로 같은 부모 밑 형제 부서와 순서를
  맞바꿀 수 있습니다 (맨 위/아래에서는 자동으로 비활성화). 부서가 많고 계층이 깊은
  실제 데이터에서는 드래그로 정확한 위치에 놓기가 까다로울 수 있어서, 버튼 클릭
  만으로도 순서를 바꿀 수 있게 만든 것입니다. 드래그앤드롭도 그대로 사용 가능합니다 —
  부서 노드를 다른 노드 <b>가운데</b>에 놓으면 하위 조직으로 이동하고, <b>위쪽/아래쪽
  가장자리</b>에 놓으면 하위조직으로 들어가지 않고 순서만 바뀝니다. 최상위로 만들려면
  상단 드롭존을 사용하세요. 순환 참조(상위 부서를 자신의 하위 부서 밑으로 이동)는
  버튼과 드래그 양쪽 모두 자동으로 차단됩니다.
- **전체 보고 모드**: 선택 상태와 무관하게 전사~최하위 부서까지 모든 조직을
  한 표(부서명 + 부서장명/ID + 응답률 + 영역·항목 점수)에 펼쳐 보여줍니다.
  "조직 계층" 항목을 켜면 부서명 컬럼이 `전사 / 　└ 본부 / 　　└ 팀`처럼 실제
  조직도를 읽듯 들여쓰기로 표시되고(레벨 번호는 별도의 작은 "레벨" 컬럼 하나로만
  붙습니다), 껐을 때는 부서명만 평평하게 나옵니다 — "레벨1, 레벨2, 레벨3..."처럼
  컬럼이 늘어서는 방식이 아닙니다.

  상단 필터 패널은 3개 그룹입니다.
  1. **표시할 레벨**: 레벨1~N 체크박스로 보여줄 조직 레벨만 고릅니다.
  2. **표시할 항목**: 조직계층/부서코드/부서장정보/인원·응답률/영역별 점수/영역별
     전년비/항목별 점수(12개)/문항별 점수(30개) 8개 그룹.
  3. **하이라이트 (파란색 볼드로 표시)**: 체크박스 + 숫자(N) 입력 4종 —
     "각 영역 하위부서 N개" / "각 영역 상위부서 N개" / "전년비 하락폭이 큰 N개" /
     "전년비 상승폭이 큰 N개". 체크하고 숫자를 입력하면 현재 필터로 걸러진 부서들
     중 (영역별 점수/전년비) 그 조건에 해당하는 셀이 파란색 굵은 글씨로 표시됩니다
     (`ANALYSIS`가 아니라 `REPORT_HIGHLIGHT_DEFS`/`state.report.highlight`에서
     로직과 기본값을 조정할 수 있습니다).

  각 그룹 옆 "전체선택 · 전체해제" 링크로 한 번에 몰아서 켜고 끌 수 있고, 모든
  체크박스는 바뀌는 즉시 표가 다시 그려집니다. "표 전체 복사" 버튼은 **현재 필터·
  하이라이트가 적용된 화면 그대로**를 표 형식(HTML)으로 클립보드에 복사하므로
  엑셀/워드에 Ctrl+V 하면 그 상태의 셀과 파란색 볼드 강조까지 그대로 들어갑니다
  (하이라이트는 CSS가 아니라 셀에 직접 인라인 스타일로 넣어서 붙여넣기에도 살아남게
  했습니다). 오래된 브라우저에서 클립보드 API가 막혀 있으면 자동으로 표 선택 + 복사
  방식으로 대체됩니다.

## 더미 데이터 재생성

```
cd scripts
python generate_dummy_data.py
```

`data/dummy_survey_data.json`, `data/org_map_2026Q2.json`을 다시 생성합니다.
더미 조직은 실제 회사 구조를 반영해 **전사(레벨1) - 본부(레벨2) - 플랫폼/팀(레벨3,
가장 메인이 되는 보고 단위 — 총 9개) - 하위팀/파트(레벨4~5)** 로 구성했습니다. 9개
플랫폼/팀 대부분은 레벨4 하위팀을 두고 있는데(핵심동인분석 회귀식이 안정적으로
계산되려면 예측변수(11개 항목) 수보다 충분히 많은 응답 표본이 필요하기 때문 —
`ANALYSIS.MIN_LEAF_SAMPLE_FOR_REGRESSION` 참고), 전체 보고 모드에서 "표시할 레벨"을
레벨3만 남기고 체크 해제하면 9개 메인 단위만 딱 걸러서 볼 수 있습니다. "회사만족"
점수는 신뢰/소통/성과/직무만족 위주로 설명되도록 의도적으로 상관관계를 주입해,
회귀분석이 실제로 유의미한 순위를 복원하는지 확인할 수 있게 했습니다. 응답률 50%
미만("조직문화팀"), 5건 미만 응답("세무팀"), 부서장 2곳 겸임("한지원") 같은 경계
사례도 일부러 포함되어 있습니다.

대시보드에 내장된 더미 데이터를 갱신하려면 이 두 파일의 내용을
`dashboard/index.html`의 `DUMMY_SURVEY_DATA` / `DUMMY_ORG_MAP` 상수에
다시 붙여넣으세요.

세그먼트(인구통계) 더미 데이터는 별도로 재생성합니다 (`dummy_survey_data.json`이
먼저 있어야 함 — 부서명을 그 파일에서 읽어옵니다):

```
cd scripts
python generate_dummy_segment_data.py
```

`data/segment_data.json`을 다시 생성합니다. 이건 대시보드에 내장되지 않고 "세그먼트
데이터 불러오기"로 직접 불러오는 파일이라, 재생성 후 붙여넣을 상수는 없습니다.

## 다음 단계 (실 데이터 연결)

1. 사내 PC에서 `pip install -r requirements.txt` 후 `scripts/xlwings_loader.py`

   레이아웃이 스크립트의 가정과 다르면 경고 메시지가 뜨니 참고해서 알려주세요.
